# Popylabs ERP – Version 1.0 MVP Specification

**Status**: Consolidated from planning chat (June 2026). Living document.

**Goal**: Deliver a focused, delightful SaaS product that Sri Lankan small businesses (physical shops + online sellers) will actually use daily because it removes friction instead of adding it.

**Launch target**: Realistic 3–4 months from start of development. Prioritize only what creates real daily value and allows showing working software to existing Popylabs clients quickly.

> **Direction update (2026):** Per product owner — this system currently generates simple **bills** / receipts (with VAT breakdown for transparency). It does **not** produce formal IRD "TAX INVOICES" under Gazette 2463/05. Full compliance with the upcoming IRD tax POS API is planned for a future release. The original spec language below has been partially revised to match current reality; treat the "Mandatory ... (Non-negotiable)" section as deferred.

---

## 1. Vision & Positioning

**"The simplest way for Sri Lankan small businesses to manage sales, stock, and records — using only their phone or computer. No extra machines. No technical knowledge needed. Works even when there is no power or internet. Produces clear professional bills."**

### Core Principles (agreed)
| Principle                  | Meaning                                      | Why it matters in Sri Lanka                  |
|----------------------------|----------------------------------------------|----------------------------------------------|
| Extremely simple           | Big buttons, clear labels, minimal steps, icons + pictures | Most users have low technical confidence     |
| True multi-device          | Works excellently 100% on phone, 100% on desktop, or hybrid | Many shops have old PC + everyone has a phone; some online sellers have only phone |
| Phone as wireless scanner  | Open same account on phone → instantly scan into active sale on desktop (or standalone) | Zero hardware cost (biggest objection)       |
| Offline-first              | Billing, stock updates, and basic records continue with no internet/power | Frequent power cuts in Sri Lanka             |
| Correct by default         | Every sale produces a clear professional bill with VAT shown | Good records + future IRD readiness          |
| Low friction start         | Sign up and start billing in < 5 minutes     | Overcome "it's a burden / expensive" feeling |
| Hybrid physical + online   | Same system for counter sales and Instagram/FB/WA orders | Real market reality for many Sri Lankan SMEs |

**Do not** position as "mobile app only". Desktop experience must feel natural and primary for traditional shops.

WhatsApp receipt sending: Basic (generate nice text/PDF/image receipt and let user copy or share). Full WhatsApp Business API integration = future work.

## 2. Sri Lankan e-Invoicing Compliance (Deferred — see note at top)

**Note**: The original "Mandatory VAT Tax Invoice" requirements (Gazette 2463/05 etc.) are **deferred**. The live system currently produces simple bills/receipts only. Full IRD POS API integration is future work.

(Original planned requirements for reference:)

Every invoice/receipt generated by Popylabs ERP **must** include:

- Clear heading: **TAX INVOICE**
- Supplier’s TIN (Taxpayer Identification Number)
- Purchaser’s TIN (if B2B / provided)
- Invoice serial number in prescribed format (typically branch-wise with monthly reset, e.g. `YYMMM_QQQQ_XXXXX` or similar — make configurable)
- Invoice date and **Delivery date**
- Place of supply
- Mode of payment (Cash, Card, Bank Transfer, etc.)
- VAT rate clearly stated (currently commonly 18%)
- VAT amount and taxable totals
- Grand total **in words** (e.g. "One Hundred Twenty Three Rupees Only")
- Values generally in LKR (handle no-cents rules where applicable)
- Proper layout/structure per latest Gazette

**Other rules**:
- 5-year retention of records (design storage accordingly)
- Support for QR / barcode on invoice (future-proofing, recommended even in v1 if easy)

The invoice engine must be easy to update if IRD changes details.

National real-time e-invoicing (RAMIS CTC) is **future** (post v1).

**Business settings** must capture: Business legal name, TIN, address, logo (optional), contact info, invoice prefix/sequence rules.

## 3. Target Users & Key Flows

### Physical Shops (with or without computer)
- Owner/staff stands at counter (old laptop or desktop preferred for billing screen).
- Uses phone camera to scan barcodes when needed (opens same SaaS on phone → "Scan Mode" that feeds the active sale).
- Completes sale → prints or sends e-receipt (WhatsApp, SMS, PDF share).
- Checks low stock / daily summary on phone or desktop at end of day.

### Pure Phone Users / Small Online Sellers (Instagram, FB, WhatsApp, TikTok shops)
- Runs entire business from phone: add products, record orders coming in via chat, update stock, generate receipts/invoices to send to customers, see daily sales.
- No desktop required.

### Hybrid Use (strong differentiator)
- Billing screen open on shop computer.
- Staff uses personal phone to scan heavy items or do quick stock checks.
- All devices stay in sync via account.

## 4. MVP v1.0 Prioritized Features

**Philosophy**: Only daily operations. One clear "wow" (evening summary). Everything else is v1.1+.

**P0** = Must have before any launch / showing to clients.  
**P1** = Strongly recommended in first 1-2 months post-launch.  
**P2** = After v1.0 stabilizes (ignore for initial build).

### 4.1 User & Access (Foundation)
- P0: Email or phone number + password registration & login (magic links or OTP nice-to-have later).
- P0: Same account works seamlessly across phone + desktop (multi-device sessions).
- P1: Basic roles — Owner (full access) vs Staff (can only do sales + limited stock view). Start with single "owner" account for v1 if it speeds launch.

### 4.2 Products & Inventory (Core)
- P0: Add / Edit / Delete products (name, selling price, optional cost price, photo, barcode/QR, category, unit).
- P0: Simple stock quantity management (manual add stock, reduce on sale, manual adjustment).
- P0: Low stock alerts (configurable threshold per product or global default; visible in dashboard + products list).
- P1: Basic product variants (e.g. Size: S/M/L, Color). Keep simple (not full matrix in v1).
- P1: Search + filter products (by name, barcode, category, low stock).

### 4.3 Sales & Invoicing (The Money)
- P0: **New Sale** (physical counter mode): Fast product search or scan, add to cart with quantity, line totals, running grand total, apply simple discount (fixed or %), select payment method, complete sale.
- P0: **New Order** (online mode): Similar to sale but with customer name/phone/note, order source tag (IG / FB / WA / Other), "pending payment" or COD options.
- P0: On every completed transaction: Generate and display a professional **bill** (PDF + thermal + WhatsApp text) with VAT breakdown.
- P0: Update stock atomically on sale completion (handle offline case carefully).
- P0: Record payment method and amount (support partial? keep simple — full payment for v1).
- P1: Reprint / resend previous invoice.
- P1: Quick "hold sale" or draft orders (nice for busy counters).

### 4.4 Dashboard & Daily Operations (The "Wow")
- P0: Home/Dashboard after login:
  - Welcome + business name
  - **Today's Summary**: Total sales (LKR + count of transactions), perhaps cash vs other breakdown
  - Low stock alert banner / list (clickable to products)
  - Quick action buttons: New Sale, New Order, Scan Product, View Products, View Reports
  - Recent activity (last 5–10 sales/orders)
- P0: **Evening / Daily Close Summary** (prominent, perhaps auto or one-tap): Sales total for the day, number of orders, top products, low/out of stock items. This is the repeatable value moment.

### 4.5 History & Reports (Basic)
- P0: Sales / Orders history list (filter by date range, search customer or invoice #).
- P0: View individual past transaction + its invoice.
- P1: Simple reports: Sales by day/week (chart or list), Best selling products, Stock movement log (basic).
- P2: More advanced analytics.

### 4.6 Offline & Sync (Critical Differentiator)
- P0: Core flows (add/edit products, record sales, adjust stock, view recent data) must work fully when offline.
- P0: Local data persists (IndexedDB / equivalent). Sales recorded locally update stock locally.
- P0: Clear "Offline Mode" indicator.
- P0: Automatic or one-tap sync when connection returns. Handle conflicts gracefully (last write wins for stock is acceptable in v1; log everything).
- P1: Background sync + conflict resolution UI for edge cases.
- Note: Login and first-time data load require internet.

### 4.7 Cross-Device Scanner (Signature Feature)
- P0: Any logged-in device can scan barcodes using camera (WebRTC + library such as ZXing or html5-qrcode).
- P0: "Scan Mode" on phone: Simple full-screen scanner that searches/adds products.
- For hybrid: When a sale is active on desktop, scanning on phone should preferably add directly to that sale (requires realtime or short-poll shared state). At minimum: Scan on phone creates/updates a sale or adds to "quick add" that appears on desktop.
- Keep implementation pragmatic for v1 (realtime via Supabase/Firestore is ideal).

### 4.8 Settings & Business Profile (Required for Compliance)
- P0: Business profile: Legal name, TIN, address, phone, logo (upload), default VAT rate, invoice numbering prefix/sequence.
- P0: Ability to configure low stock threshold, currency (LKR), date formats.
- P1: Multiple "branches" or locations with separate invoice sequences (important for serial format).

### 4.9 Out of Scope for v1.0 (explicitly delayed)
- Full WhatsApp Business API automation / catalogs / chatbots
- Advanced roles & permissions, multiple staff accounts with fine-grained control
- Customer CRM (full profiles, loyalty, history beyond basic)
- Purchase orders / supplier management / accounting exports
- Multi-currency, heavy e-commerce integrations
- National e-invoicing API submission
- Advanced inventory (batches, expiry for pharmacies — v1.5+)
- Subscriptions / billing for the SaaS itself (manual onboarding for first clients)

## 5. Detailed Screen-by-Screen (v1.0)

### 5.1 Login / Register
- Logo (Popylabs ERP or Popylabs branded)
- Phone number or Email + Password
- Big primary "Login" button
- "Create account" / "Forgot password?"
- Responsive: Phone = full screen; Desktop = clean centered card
- Offline: N/A (needs network)

### 5.2 Dashboard (Home)
- Header: Business name + user + "Offline" pill when applicable + sync status
- Today's Summary card(s): Revenue today, # Transactions, perhaps average order value
- Prominent Low Stock warning (count + "View" link)
- Quick Actions row/grid (large tappable targets):
  - New Sale (primary for shops)
  - New Order (for online)
  - Scan (opens camera scanner)
  - Products
  - Reports / History
- Recent Activity feed (last sales with amount + time, tappable to detail)
- Desktop layout: Summary + actions side-by-side or two columns; Phone: stacked vertical

### 5.3 Products
- Top: Search input + "+ Add Product" (floating or prominent)
- Filter chips: All / Low Stock / Out of Stock / Categories
- List or grid (cards on phone, table on desktop):
  - Small photo (or placeholder)
  - Name + barcode (if present)
  - Selling price
  - Current stock (color coded red if low)
- Tap/click → Edit product drawer or screen
- Add/Edit form:
  - Name (required)
  - Selling Price (required)
  - Cost Price (optional)
  - Barcode (manual or "Scan to fill")
  - Category (free text or simple select)
  - Stock quantity (initial)
  - Low stock threshold
  - Photo (camera or gallery upload — PWA friendly)
  - Save / Delete (with confirmation)

### 5.4 New Sale (Physical Billing)
- Two sections or tabs: Product browser + Current Cart
- Fast product search (name/barcode) or big "Scan with Phone / This Device" button
- Product results show name, price, stock, quick + button
- Cart: List of lines with qty stepper, unit price, line total, remove
- Bottom / side summary: Subtotal, Discount (simple input), Grand Total
- Payment method select (Cash / Card / Transfer / Other) + "Complete Sale" big button
- On complete: 
  - Atomically create sale + update stock
  - Show success + the generated bill (PDF auto-download + modal with reprint/thermal/copy actions)
- Must feel fast on both phone and desktop. Big tap targets.

### 5.5 New Order (Online Sellers)
- Similar cart flow to New Sale
- Extra fields at top or checkout: Customer name, phone, notes, source (IG/FB/WA/Other), expected delivery or status
- "Create Order" instead of "Complete Sale" (may support "mark as paid" later)
- Still generates a proper bill / receipt for the customer

### 5.6 Scanner (Dedicated or in-flow)
- Full screen camera view (back camera preferred)
- Overlay guides + "Point at barcode"
- On successful scan: Lookup product → show name/price/stock → "Add to current sale" or "Add to new sale" or quick stock check
- "Manual entry" fallback (type barcode)
- Close / done button

### 5.7 Sales / Orders History
- Search + date filter (today / this week / custom)
- List of transactions (date/time, invoice #, customer if any, total, payment method)
- Tap → Detail view with full line items + the original bill (reprint/share)

### 5.8 Reports (Light)
- Simple tabs or sections: Sales Summary, Top Products, Low Stock
- Date range picker (basic)
- Numbers + very simple bar or list views (no heavy charting in v1)

### 5.9 Settings
- Business Profile form (TIN, name, address, logo upload, invoice prefix)
- Low stock default threshold
- Invoice template notes (footer text)
- Account: Change password, logout
- (Later: Subscription / billing status for the SaaS)

## 6. Technical & Architecture Notes (for implementation)

- **Frontend**: Modern responsive web (mobile-first but excellent desktop). PWA capable (installable on phone and desktop, works offline).
- **Data**: Must support eventual consistency for offline. Every mutation (sale, stock change, product edit) should be timestamped and queued for sync.
- **Stock safety**: Critical — a sale that was created offline must correctly decrement stock on sync. Prefer recording "sale events" rather than just current quantity when possible.
- **Bill/receipt rendering**: Must be pixel-reasonable for printing or sharing (A4 or thermal 80mm friendly). Generate PDF client or server side. Clear VAT breakdown + business details. (Full IRD-mandatory layout deferred until POS API integration.)
- **Realtime / Scanner**: For best hybrid experience, use a backend with realtime subscriptions (so phone scan can affect desktop cart live). Polling fallback is acceptable for v1.
- **Multi-tenancy (SaaS)**: Each business is isolated. Start with simple model (user has one business, or user → organizations). Row Level Security or separate schemas later.
- **Auth**: Email/phone + password minimum. Consider phone OTP for Sri Lankan ease of use.
- **Storage**: Product photos — small compressed images. Use CDN or Supabase Storage / Firebase Storage.
- **Error handling**: Graceful degradation when offline. Never lose user-entered sale data.

## 7. Success Criteria for v1.0 Launch Readiness

A new user can:
1. Sign up and create their business profile (TIN etc.) in < 3 minutes.
2. Add 10–20 products (some with barcodes and photos).
3. Perform a full day of mixed sales + orders while offline, with stock correctly decreasing.
4. On reconnect, everything syncs without data loss.
5. Generate and share/print a clear professional bill (with VAT breakdown) that serves as a good customer record.
6. See a useful end-of-day summary that helps them understand what sold and what needs re-ordering.
7. Use comfortably on both an old Windows laptop browser and a modern Android phone.
